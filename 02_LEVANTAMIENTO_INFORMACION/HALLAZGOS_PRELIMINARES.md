# HALLAZGOS PRELIMINARES (v0.2) — para validar con el practicante

## H1. Reposición reactiva: sin stock mínimo ni uso del control de stock del sistema  → candidato a PROBLEMA CRÍTICO (cap. VIII)
| Elemento | Contenido | Fuente |
|---|---|---|
| Situación observada | La revisión de existencias se hace mirando los estantes, solo cuando hay dudas. Un producto se considera "bajo" cuando **ya no hay**. No existe una cantidad mínima definida | [PRA] B4 p.7–9 |
| Evidencia disponible | Rapifac sí muestra el stock, pero no se usa para decidir la reposición. Se han agotado productos y al cliente se le informó que no había | [PRA] B4 p.6, p.10 |
| Contexto | Pedidos una vez por semana; tiempo de entrega de 4 días en promedio; entre 300 y 400 artículos; aviso a los jefes por WhatsApp; los jefes deciden qué y cuánto comprar | [PRA] B3–B4 |
| Posibles causas (por validar) | Falta de stock mínimo o punto de reorden; no se usa el módulo de stock; no hay una revisión programada; la comunicación es informal (WhatsApp sin formato) | Análisis |
| Consecuencias (por cuantificar) | Ventas perdidas o derivadas a 2 competidores cercanos; el cliente queda insatisfecho | Por cuantificar |
| Propuesta preliminar | Clasificación ABC de los productos más vendidos + stock mínimo y punto de reorden para los productos A, calculados con el consumo semanal y el tiempo de entrega de 4 días + revisión programada antes del pedido semanal + uso del stock de Rapifac + lista estandarizada de reposición | Propuesta (no implementada) |

| Elemento | Contenido | Fuente |
|---|---|---|
